## ✨ New features {#✨-новые-возможности}

- The application page now shows the team's process cards and a separate folder for models, making it easier to find your way around your diagrams and quickly locate the ones you need.  
- A user profile has been added to the application page: colleagues can easily see who is responsible for processes and architecture.  
- The same page now shows role and architecture element cards, helping to connect processes with the company's actual structure.  
- A model trash bin has been added: deleted diagrams can be safely restored without contacting support.  
- Comments now have an "Attention" section with a full list, counters and quick mentions of colleagues, so important discussions are no longer lost.  
- The work context now includes a "Team updates" block that shows which materials colleagues have published in the knowledge base over the week.  
- The relationship map can show the state as of a specific version date, making it easier to analyze how architecture and processes have changed over time.  
- In the process registry, edits can be saved directly from table cells, and the selected table layout is remembered, which speeds up work with large lists.  
- The review module now has bulk decisions and an "Unresolved only" filter, making it noticeably faster to go through comments on models.  

## 🚀 Improvements {#🚀-улучшения}

- Registry import and export are more reliable: operations complete correctly, do not get stuck in the "in progress" status and do not leave partially loaded data.  
- Process history and attachments in the registry are now strictly separated by team, which improves transparency and security of collaboration.  
- Working with registry templates is more convenient: the template flag is not reset when going back, and catalog templates are not blocked by the limits of the current registry.  
- Diagnostics of connections to models and external services are more robust: temporary network failures and response errors do not interfere with the check and produce clearer statuses.  
- The application page, roadmap board and marketing pages look cleaner and have better contrast, including in the dark theme and for screen reader users.  
- Simulation validation and calculation errors are now shown in Russian, making it easier to understand the causes and fix models.  
- Feedback progress shows whole percentages and correct statuses even in old tabs, making reports clearer.  

## 🔧 Fixes {#🔧-исправления}

- Registry import and export work better: operations can be reliably cancelled, the "completed" status appears only together with the result, and data is not corrupted on errors.  
- Models and processes no longer get "stuck" in inaccessible teams: data is cleaned up correctly when a team is deleted or changed.  
- Collaboration in AI chats is more predictable: history, attachments and chat turns always belong to the active team and are not mixed between different teams.  
- Model access requests no longer appear in the "Shared with me" section and do not interfere with exports until access is actually granted.  
- Creating employee cards in the org structure no longer affects other people's records and works only within the initiator's scope.  
- Switching between sections and teams is more stable: late responses do not disrupt a transition already in progress, and tab state is updated correctly after a team change.

::: details Image signature verification (Cosign)
All Docker images are cryptographically signed using [Sigstore Cosign](https://docs.sigstore.dev/). To verify the authenticity of the image:

**1. Install Cosign:**
```bash
# macOS
brew install cosign

# Linux
curl -sSL https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64 -o /usr/local/bin/cosign
chmod +x /usr/local/bin/cosign
```

**2. Verify the signature:**
```bash
cosign verify \
  --certificate-identity-regexp="https://github.com/KotskinKotskin/stormfullstack/*" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com" \
  registry.stormbpmn.com/stormbpmn-enterprise/stormbpmn_fullstack_enterprise:9.26.14
```

Successful verification guarantees that the image was built in the official CI/CD and has not been tampered with.
:::
