## ✨ New Features {#✨-новые-возможности}

- **Process Simulations: Public Reports and Promo Emails**  
  You can now publish simulation reports as separate public pages and share them with colleagues and external stakeholders. For some users, a promo email titled "We Ran a Simulation of Your Process" is available, featuring brief conclusions and optimization ideas.

- **New Metrics in Simulations: Time, Load, and Economics**  
  Simulation reports now include extended metrics: Little's Law based on active time, throughput, resource engagement, and more precise economics (P&L and V&V). This helps better understand where the process "gets stuck," how loaded the performers are, and how the financial outcome changes.

- **"Optimization" Button in the BPMN Editor**  
  The diagram editor now features an "Optimization" button that checks the process's suitability for automated analysis and suggests areas for improvement. This simplifies the first step toward optimization without requiring deep modeling knowledge.

- **New Report View for Simulation Cases**  
  The case page now includes tabs for scenarios and a full-screen report mode. This makes it easier to compare different scenarios and analyze the results of specific runs in detail.

- **Public Wiki and Report Pages**  
  Wiki pages can be published as separate public pages with a convenient widget and a button to navigate to the simulation (if available). This simplifies knowledge and documentation sharing with external participants.

- **Comments: Statuses, Importance, and Wiki Anchoring**  
  Comments now feature "resolved/open" statuses, an "important" flag, and a filter for resolved discussions. Comments can be anchored to specific blocks of a Wiki page, allowing you to discuss a particular text fragment rather than the entire page.

- **Comments: Editing and Deleting Your Messages**  
  Users can now edit and delete their own messages in comments. This allows for quick correction of inaccuracies and keeps discussions up to date.

- **Viewing Effective Access Rights in Wiki**  
  The Wiki now includes a view for "effective" access rights, showing what a user can actually do with a specific page. This reduces confusion regarding permissions and simplifies administration.

- **Public Simulation Report as a Widget**  
  The public simulation report is available as a standalone widget with a clean header and a soft banner. It is convenient to embed in external materials and present to interested parties.

- **Storm Master — Assistant in Chat and Emails**  
  A mascot named "Storm Master" has been introduced in chat and emails as a unified assistant image. This makes interaction with hints and recommendations more understandable and recognizable.

- **Emails and DES Showcase: Flexible Retention Scenarios**  
  The DES simulations showcase has become a separate "trigger" for emails with a configurable audience and a custom email template. Added features include daily email generation with sending on the nearest working morning, unread badges, unsubscribe options, and a toggle in the profile.

- **Yandex Integration for User Profile**  
  When logging in via Yandex, the name and avatar are automatically pulled into the profile. This saves time on account setup and makes the profile more recognizable.

- **Graph: Node Addresses and Access Rights**  
  The process graph now includes node addresses, node providers, gates, and rights. This provides greater control over who can work with specific parts of complex diagrams and how.

## 🚀 Improvements {#🚀-улучшения}

- **Simulations: Easier to run and analyze results**  
  The simulation item in the sidebar is now visible by default, and the run date is displayed in the report header. The "lineage" of simulations is highlighted in the list rather than "muting" adjacent elements, which simplifies navigation between related runs.

- **Reports and charts interface**  
  A dedicated charts toolbar has been introduced, featuring time-based zoom, synchronized ranges, and fullscreen mode. Configuration panels are now wider, reports open in the top tab, and the selection frame on the simulation canvas is more prominent.

- **Simulation and economics metrics accuracy**  
  Improved handling of cases that did not reach the end of the process, and Little's Law is now calculated based on all exited cases. The alignment of P&L time series with financial reports has been adjusted to ensure more accurate process economics.

- **Resource management in processes**  
  A dedicated "resource engagement in process" block has been added, along with alignment of the corresponding forms. This helps better visualize executor workload and identify bottlenecks.

- **Wiki: Import/Export and draft management**  
  Markdown import/export for Wiki now supports tables and images, simplifying the migration of complex documents. Draft handling has been improved: instead of a full page reload, a graceful retry of the load is used.

- **Public pages and simulations**  
  The public Wiki page and public simulation report now operate on a unified widget, featuring a clear CTA and proper redirection to the list when a simulation is unavailable. This makes the behavior of public links predictable for recipients.

- **Comments: Managing discussion flow**  
  The ability to mark threads as "important," quickly filter resolved discussions, and anchor them to specific Wiki blocks has been added. This helps prevent losing key decisions and allows for faster return to relevant topics.

- **Letters and DES showcase: Quality and control**  
  A preliminary "circuit breaker" for clearing drafts before live campaign launches has been added. The logic for triggers has been improved (trigger subject separated from the anchor, prohibition of duplicates, pessimization with a re-pass) to prevent users from receiving unnecessary or duplicate letters.

- **Marketing and events**  
  In the events mega menu, "Offline" has been renamed to the clearer "In-person," and past events no longer push out current ones. The domain banner remembers its dismissal state to avoid interference during repeat visits.

- **Chat and AI analysis**  
  Letters and chat now formulate commitments more precisely: they do not mention "remarks" without facts and more accurately assess processes without revenue (not marking them as "unprofitable" without grounds). This increases trust in recommendations and reduces the risk of misinterpretation.

- **BPMN editor: Usability**  
  The editor island has been aligned with the simulation toolbar style, and an autosave indicator has been added. Keyboard copying of element names and tooltip display have been improved to make working with diagrams faster and more reliable.

- **Access and security**  
  Access control list (ACL) handling during deletion and restoration has been improved to ensure permission changes are not lost during team work. Viewing effective permissions in Wiki helps quickly identify and resolve access issues.

- **Interface and branding**  
  Typography and covers in the mega menu have been updated, and handling of connections to brand resources has been improved. This makes the product visually more cohesive and polished.

## 🔧 Fixes {#🔧-исправления}

- **Simulations: stability and predictability**  
  If a simulation is unavailable, the user is correctly returned to the list, and clicks on the scenario map no longer affect the table below it. The causes preventing the system from reaching a steady state have been fixed, and the display of these causes in the report has been improved.

- **Case and metric accounting**  
  Consumables for cases that did not reach completion are now correctly accounted for, and Little's Law is applied to all exited cases, not just those that completed the process. This eliminates discrepancies in time and load metrics.

- **Comments and notifications**  
  Issues with duplicating read lists and incorrect load when counting by diagrams have been resolved. The showcase no longer sends notifications to the author about their own runs.

- **Wiki and trash**  
  Residual issues with access rights and restoring pages from the trash have been fixed. Draft behavior has become more predictable, with no full page reloads during temporary errors.

- **Chat and retention emails**  
  Conversations started from emails now correctly understand which schema they relate to. Prompt phrasing has been corrected to avoid creating false expectations for users.

- **Marketing panels and banners**  
  The "Events" panel now correctly navigates to the address upon clicking and does not hide current events as past. The domain banner correctly remembers its closure and does not reappear unnecessarily.

- **Interface details**  
  The help panel on the public report page has been fixed, the resource engagement block in the form has been aligned, and height and sorting in table views have been improved. Tooltips in BPMN now correctly escape data, and copying the name works from the keyboard.

- **Integration reliability**  
  OAuth token handling has been updated so that external assistant sessions do not drop after a few hours. This reduces the number of unexpected logouts and re-authentications.
