## ✨ New features {#✨-новые-возможности}

- Login page branding for Enterprise: company name and logo (light and dark), custom heading and text above the form, brand color for the login page and application, selection of login methods and "Technical Support" and "Knowledge Base" links. Configured in the initial setup wizard (the "Branding" step) or later by an administrator. For details, see the [Branding and login page](../configure/branding.md) article.
- Email confirmation now uses a code from the email: you can enter it directly on the "Check your email" screen, which speeds up the first system login and reduces activation errors.
- A dedicated screen has been added to the approvals registry: all approvals are collected in one place, making them easier to view, analyze, and monitor status.
- An interactive table component has been added to the new table page in the data registry: you can conveniently view the structure, work with columns, and prepare the table for use.
- System tables now feature a new display format with virtualization and hierarchy support: large lists and tree structures load faster and remain easy to navigate.
- In the employee card, you can edit personal data and photo directly on the page, as well as work with tabs displayed as visual "pills" with quick actions on hover.
- Employee avatar upload has become more convenient: first, you select a file, then crop it, and the final photo is always displayed in a neat square format.
- Comments on pages have been added to the wiki: teams can discuss content directly in the document context without losing the discussion history.
- Navigation has been improved on the process surveys page and in the surveys registry: it is easier to switch between survey creation, the list, and responses, as well as to see a summary of all collected responses.

## 🚀 Improvements {#🚀-улучшения}

- The design of the cookie usage dialog has been updated: it is now visually cleaner and better aligns with the overall STORM BPMN style.
- The folder icon color is now set and stored for the entire team, which helps visually structure the workspace and find specific sections faster.
- The "What's New" section feed now displays the latest announcements at the top, ensuring important updates are always visible.
- The employee card screen now uses a unified display template: a skeleton during loading, clear "not found" and "no access" states, and neat error handling with the ability to retry loading.
- Entity pages in the application interface now also display a clear "not found" state, reducing confusion when working with links.
- The hint block in role and resource search has been improved: results are grouped more clearly, speeding up the search for required objects.
- The process simulation interface has improved handling of logical operators: the system warns about incorrect configurations in advance to avoid errors before execution.
- In the process model architecture section, anonymous users now see the login screen, making interface behavior predictable and protecting service data.
- Hierarchy tables have improved filter and branch expansion behavior: the tree behaves predictably, rows are not duplicated, and navigation remains convenient even with complex filters.
- The employee registry has improved handling of the "Roles" column — data can be conveniently sorted and analyzed.
- Team rating is now calculated only for active participants, excluding invited users, making metrics more accurate.
- Mass team notifications upon creating new process models and versions have been disabled in the notifications interface to reduce "noise" and leave only truly important messages.

## 🔧 Fixes {#🔧-исправления}

- The email confirmation code process is now more reliable: the code is entered correctly per cell, it is not erased upon accidental keypress, resubmission does not conflict with validation, and retry limits work predictably.
- Upon activation and system login, users receive clearer error messages and see only the statuses that actually apply to them.
- Process models are no longer blocked until the session loads, and the "Shared with me" section correctly accounts for team restrictions, eliminating unexpected restrictions on working with models.
- On diagrams, elements in the lower part of the schema are no longer obscured by the support panel and AI assistant, improving visibility and work with large models.
- The comments and wiki panels more reliably save typed text: entered comments are not lost when refreshing the page or during loading failures.
- Links to employees (including those with legacy parameters in the address bar) now always open the correct card or correctly indicate lack of access.
- Surveys for registry processes and their responses are correctly opened from the registry, are not lost when switching surveys or reloading the page, and link access is restricted according to permissions.
- In the approvals and surveys section for processes, situations where some responses might not display in the summary have been fixed.
- In multi-team work, errors related to access to other teams' models, attachments, and roles have been resolved: the system correctly distinguishes teams and prevents unexpected denials or failures.
- In the architecture section, issues with permissions and user identification have been resolved, making the viewing of architecture graphs more stable.
- Rare errors when working with files and large objects in models have been fixed to ensure that broken links do not affect other elements.
- In payment details for contract renewals, data is now always retrieved from the correct team account, reducing the risk of errors in documents.
