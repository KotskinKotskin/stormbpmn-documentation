# Как работают лицензии

StormBPMN поддерживает два типа лицензий для управления доступом пользователей к системе.

::: tip Типы лицензий
**Именные лицензии** - для конкретных пользователей  
**Конкурентные лицензии** - для одновременной работы
:::

## Типы лицензий

### Именные лицензии

**Именные лицензии** позволяют входить в систему конкретным пользователям в любой момент времени.

**Принцип работы:**

-   Количество лицензий = количество активных учетных записей
-   Ограничение распространяется на учетные записи во **включенном состоянии**
-   Состояние пользователей отображается в административном интерфейсе

**Пример:** При наличии 30 именных лицензий ровно 30 пользователей могут иметь активные учетные записи.

### Конкурентные лицензии

**Конкурентные лицензии** позволяют иметь в онлайне (в диапазоне 1 минуты) определенное количество одновременно подключенных пользователей.

**Принцип работы:**

-   Количество лицензий = количество одновременных сессий
-   Квант времени для проверки: **1 минута**
-   Ограничение на количество зарегистрированных учетных записей **не действует**
-   Проверка включенности пользователей **не выполняется** с точки зрения лицензий. Все еще проверяется для возможности входа.

**Пример:** При наличии 30 конкурентных лицензий 30 человек смогут работать в системе одновременно.

## Общие принципы лицензирования

### Дополнительная лицензия

::: tip Бонусная лицензия
**Система автоматически предоставляет +1 лицензию к заявленному количеству** для обеспечения бесперебойной работы администраторов.

Например: при покупке 30 лицензий фактически доступно 31 место.
:::

### Кто подвергается лицензированию

**Лицензированию подвергаются только пользователи с учетными записями в системе:**

-   **Зарегистрированные пользователи** - те, кто прошел процедуру регистрации
-   **Импортированные пользователи** - добавленные через административный интерфейс
-   **Пользователи из внешних систем** - при интеграции с LDAP/Active Directory

Словом, любая учетная запись.

::: warning Исключения
**Анонимные посетители** (кто не входит в систему) не учитываются при подсчете лицензий.
:::

## Активация инсталляции

::: warning Для каждой Enterprise-инсталляции нужен свой ключ v2
Используйте заново выпущенный ключ **`LICENSE_KEY_V2`**. Переменная **`LICENSE_KEY`**, лицензии
v1 и ранее выданные ключи новой версией больше не принимаются. Ключ от другой инсталляции
также не подойдёт.
:::

**Как получить и установить ключ:**

| Шаг | Действие |
| --- | -------- |
| 1 | Откройте **`/admin-onboarding`** на нужной инсталляции (например, `https://ваш-домен/admin-onboarding`) |
| 2 | Скопируйте **весь код активации без сокращения** из блока «Ваш активационный код» |
| 3 | Передайте полный код менеджеру и получите `LICENSE_KEY_V2` именно для этой инсталляции |
| 4 | Сохраните `LICENSE_KEY_V2` в конфигурации или хранилище секретов; значение `LICENSE_KEY` сохраните в защищённом хранилище до конца окна отката |
| 5 | Перезапустите все экземпляры приложения и дождитесь успешных health checks |
| 6 | Проверьте на `/admin-onboarding`, что лицензия активна, затем проверьте вход обычного пользователя |

**Отдельный ключ нужен каждой инсталляции.** Production, каждый тестовый контур, резервная
площадка (DR), клон и перенесённая в новое окружение система лицензируются отдельно. Перед
массовым обновлением составьте их список и заранее запросите ключ для каждой.

::: tip Код активации изменился
Если на экране `/admin-onboarding` показан другой код, запросите новый `LICENSE_KEY_V2` у
менеджера и передайте ему весь отображаемый код без сокращения.
:::

**Если обновление уже выполнено без подходящего `LICENSE_KEY_V2`:**

Бэкенд может запуститься в заблокированном лицензионном режиме, чтобы сохранить владельцу путь
восстановления. Сам факт запуска и успешный health check не подтверждают доступ обычных
пользователей.

1. Войдите как владелец — учётная запись из администраторской команды — и откройте
   `/admin-onboarding`. Обычным пользователям этот режим не предназначен.
2. Скопируйте полный код активации и получите ключ у менеджера.
3. Задайте `LICENSE_KEY_V2` и перезапустите все экземпляры приложения.
4. Дождитесь успешных health checks, проверьте статус лицензии и вход лицензированного обычного
   пользователя. Данные при этом сохраняются.

### Переключение и откат версии

До обновления сохраните действующее значение `LICENSE_KEY` в защищённом хранилище секретов и
не удаляйте его до окончания согласованного окна отката. Новую версию запускайте с
`LICENSE_KEY_V2`. Если требуется откат на версию, которая использовала лицензию v1, верните в
конфигурацию `LICENSE_KEY`, восстановите совместимую базу данных и образ по процедуре отката,
затем проверьте вход обычного лицензированного пользователя. После закрытия окна отката старый
секрет можно удалить по принятой процедуре управления секретами.

### Диагностика и восстановление

- Если полный код активации на `/admin-onboarding` отличается от кода, для которого выдан
  текущий ключ, передайте новый код менеджеру и запросите перевыпуск `LICENSE_KEY_V2`.
- Если отображается состояние **`SIGNATURE_UNAVAILABLE`**, не запрашивайте перевыпуск только
  из-за этого состояния: сохраните ключ без изменений, соберите логи и обратитесь в поддержку
  для восстановления проверки лицензии. Замена ключа сама по себе эту причину не устраняет.
- После любого восстановления дождитесь health checks, убедитесь, что лицензия активна, и
  проверьте вход и лицензированную функцию под обычной учётной записью, а не только под владельцем.

### Резервное копирование и DR

Храните `LICENSE_KEY_V2` в защищённом хранилище секретов, которое входит в DR-процедуру или
восстанавливается отдельно от базы данных. Не рассчитывайте, что дамп PostgreSQL содержит этот
секрет. После восстановления или переключения на DR-площадку откройте `/admin-onboarding` и
сравните полный код активации с кодом, для которого выдан сохранённый ключ. Если код изменился,
передайте новый код менеджеру и получите отдельный `LICENSE_KEY_V2`; если не изменился,
используйте сохранённый ключ. В обоих случаях завершите проверку входом лицензированного
обычного пользователя и выполнением доступной ему лицензированной функции.

## Управление лицензиями

### Выдача лицензий

По умолчанию автоматическая выдача лицензий **отключена**.

**Стандартный алгоритм для всех типов лицензий:**

| Шаг | Действие                      | Описание                                                          |
| --- | ----------------------------- | ----------------------------------------------------------------- |
| 1   | **Регистрация пользователя**  | Пользователь впервые входит или регистрируется                    |
| 2   | **Активация администратором** | Администратор включает пользователя в административном интерфейсе |
| 3   | **Доступ к системе**          | Пользователь получает возможность входить в систему               |

::: tip Автоматическая выдача лицензий
Для упрощения процесса в административной панели можно включить опцию **"Автоматическая выдача лицензии любому, кто залогинился в систему"**.

В этом случае пользователь после регистрации сразу получает доступ к системе.
:::

### Учётные записи «Ожидает активации»

Чтобы шаг 1 работал при выключенной авто-выдаче, включите настройку **createPendingEnterpriseUsers** («Создавать неактивную учётную запись, если авто-выдача лицензий отключена», группа «Бизнес-логика»). Тогда любая попытка входа или регистрации (SSO, LDAP, форма регистрации) создаёт **неактивную** учётную запись:

-   учётная запись **не потребляет лицензию**, пока не активирована — деактивированные пользователи в подсчёте лицензий не участвуют;
-   пользователь при каждой попытке входа видит сообщение «обратитесь к администратору»;
-   в разделе «Управление пользователями» такие учётные записи подсвечены статусом **«Ожидает активации»** (отдельно от вручную деактивированных);
-   администратор активирует учётную запись одним кликом — с этого момента она потребляет лицензию. Если свободных лицензий нет, активация завершится ошибкой «Нет свободных лицензий»;
-   восстановление пароля и письмо активации **не активируют** такую учётную запись — только администратор.

Если настройка выключена (по умолчанию), вход неизвестному пользователю при выключенной авто-выдаче запрещён, учётная запись не создаётся.

## Исчерпание лицензий

### Именные лицензии

**Ситуация:** Все места заняты пользователями

**Последствия:**

-   Пользователи **не смогут войти** в систему
-   **Администратор сохраняет доступ** к административной панели

**Решение:**

1. Администратор входит в административную панель
2. Отключает лишних пользователей, что освобождает лицензии

### Конкурентные лицензии

**Ситуация:** Достигнут лимит одновременных подключений

**Последствия:**

-   Новые пользователи **не смогут войти** в течение 1 минуты
-   **Администратор сохраняет доступ** к административной панели
-   При завершении сессий другими пользователями места освобождаются автоматически

**Решение:**

1. **Ожидание** - места освободятся автоматически при выходе пользователей
2. **Принудительное завершение** - администратор может завершить сессии пользователей через административную панель

::: warning Мониторинг лицензий
Регулярно отслеживайте использование **именных** лицензий через административную панель для предотвращения блокировок
:::

## Истечение срока лицензии

При истечении срока действия лицензии:

::: danger Блокировка доступа
**Все пользователи, включая администраторов, не смогут войти в систему**

Для восстановления работы необходимо обновить лицензионный ключ.
:::

## Страница статуса лицензии `/license-active`

На Enterprise-установке публичного сайта нет: любой заход на адрес вне приложения (не `/app/...`)
автоматически переводит посетителя на страницу **`/license-active`**. Это «входная точка» вашей
установки, и её поведение зависит от того, авторизован ли посетитель:

-   **Авторизованный пользователь** видит приветствие с 3-секундным отсчётом и автоматически
    переходит к своим процессам. Переход можно отменить кнопкой — тогда останется страница
    со статусом лицензии.
-   **Неавторизованный посетитель** видит статус лицензии (тип, срок действия) и кнопки действий:
    вход, регистрация (если включена настройка `showRegistraton`), сброс пароля.

::: tip Регистрация и согласие с условиями
С версии 6.6.6668 при активной Enterprise-лицензии чекбокс согласия с условиями использования
на форме регистрации **скрывается автоматически** — корпоративным пользователям не нужно
принимать публичную оферту. Отдельная настройка для этого не требуется.
:::

### Кастомизация страницы лицензии

С версии 6.6.6668 на страницу `/license-active` можно добавить собственный HTML-блок — например,
корпоративное приветствие, контакты внутренней поддержки или ссылки на регламенты.

**Как настроить:**

1. Откройте **Административную панель → Настройки приложения → группа «Бизнес-логика»**.
2. Найдите настройку **«HTML-блок на странице статуса лицензии»** (`licensePageHtml`) и
   вставьте свой HTML в текстовое поле.
3. Убедитесь, что у настройки включён тумблер **«Настройка видимости»** — страницу видят
   неавторизованные посетители, без видимости HTML до них не доедет.

**Поведение:**

-   Если HTML задан — он показывается **над** статусом лицензии, а сам статус сворачивается
    в раскрываемую панель.
-   Если настройка пуста — страница выглядит как раньше: развёрнутый статус лицензии.
-   HTML проходит санитизацию (вырезаются скрипты и опасные конструкции), картинки автоматически
    ограничиваются по ширине. Используйте статичную разметку: заголовки, текст, ссылки, изображения.

Изменения применяются сразу, перезапуск не нужен.
