# Метрики процессов

Управление метриками процессов через REST API. Общие правила (авторизация, лимиты) — в
[обзоре REST API](./README.md).

## Управление метриками процессов

### Обновление значения метрики

**Путь:** `POST /public-api/v1/processes/metrics`

Метод позволяет заполнять или обновлять значения метрик для процессов. Сама метрика (пользовательское поле) должна быть предварительно создана в интерфейсе системы.

### Структура запроса

```json
{
    "processId": "94d2e63f-f84a-40d4-b4a3-592b0cc7c7d9",
    "metricName": "avg_execution_time",
    "metricValue": 45.5,
    "metricPlanValue": 30.0,
    "comment": "Значение за январь 2025"
}
```

### Параметры запроса

| Поле                | Тип        | Обязательное | Описание                                                                                                   |
| ------------------- | ---------- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| **processId**       | `UUID`     | ✅           | Идентификатор процесса                                                                                     |
| **metricName**      | `string`   | ✅           | API-имя метрики: поле «API Name» в настройках пользовательского поля, а не его название                    |
| **metricValue**     | `number`   | 📄           | Фактическое значение метрики                                                                               |
| **metricPlanValue** | `number`   | 📄           | Плановое значение метрики                                                                                  |
| **comment**         | `string`   | 📄           | Комментарий к значению                                                                                     |
| **period**          | `date`     | 📄           | Только у метрики с периодичностью: первый день периода (`YYYY-MM-DD`), см. [ниже](#метрика-с-периодичностью) |
| **metricDate**      | `datetime` | 📄           | Не используется: сервер не сохраняет это поле, период им не задаётся                                       |

### Структура ответа

```json
{
    "processId": "94d2e63f-f84a-40d4-b4a3-592b0cc7c7d9",
    "metricName": "avg_execution_time",
    "metricValue": 45.5,
    "metricPlanValue": 30.0,
    "delta": 15.5,
    "comment": "Значение за январь 2025",
    "metricDate": null,
    "period": null
}
```

### Поля ответа

| Поле                | Тип        | Описание                                                                                  |
| ------------------- | ---------- | ----------------------------------------------------------------------------------------- |
| **processId**       | `UUID`     | Идентификатор процесса                                                                    |
| **metricName**      | `string`   | API-имя метрики                                                                           |
| **metricValue**     | `number`   | Фактическое значение метрики                                                              |
| **metricPlanValue** | `number`   | Плановое значение метрики                                                                 |
| **delta**           | `number`   | Отклонение от плана с учётом направления метрики                                          |
| **comment**         | `string`   | Комментарий к значению                                                                    |
| **period**          | `date`     | У метрики с периодичностью — первый день периода, в который записано значение; иначе `null` |
| **metricDate**      | `datetime` | Всегда `null`                                                                             |

### Метрика с периодичностью

У метрики может быть задана периодичность: неделя, месяц, квартал или год. Тогда план, факт и комментарий хранятся за каждый период отдельно, и запрос записывает значение одного периода.

- **Какой период.** `period` — первый день периода: у недели понедельник, у месяца первое число, у квартала 1 января, 1 апреля, 1 июля или 1 октября, у года 1 января. Без `period` значение пишется в текущий период по московскому времени.
- **Значение периода заменяется целиком.** Факт и комментарий периода становятся такими, как в запросе: если поля нет в запросе, в периоде его не остаётся. Нужен хотя бы один из `metricValue` и `metricPlanValue`.
- **План переносится.** Если у периода нет своего плана, действует план ближайшего прошлого периода. В ответе `metricPlanValue` и `delta` считаются с перенесённым планом.
- **Будущие периоды.** В будущий период можно записать только план.
- **Что видно в интерфейсе.** В карточке процесса, реестре и выгрузке у такой метрики показан факт последнего периода, где он есть, и план этого же периода.

Пример — факт и план месячной метрики за октябрь 2026:

```json
{
    "processId": "94d2e63f-f84a-40d4-b4a3-592b0cc7c7d9",
    "metricName": "avg_execution_time",
    "metricValue": 45.5,
    "metricPlanValue": 30.0,
    "period": "2026-10-01"
}
```

В ответе — значение этого периода и `"period": "2026-10-01"`.

Ошибка `400`:

- `period` передан метрике без периодичности;
- `period` — не первый день периода (в тексте ошибки — ожидаемая дата);
- факт за будущий период;
- пустые и `metricValue`, и `metricPlanValue`;
- у обязательной метрики не остаётся ни одного периода с фактом.

::: tip Сценарии использования
- **Интеграция с BPMS**: Автоматическая загрузка метрик производительности из систем исполнения процессов (Camunda, Activiti и др.)
- **BI системы**: Экспорт аналитических показателей из хранилищ данных
- **Мониторинг SLA**: Автоматическое обновление показателей соблюдения SLA
:::
