# Диаграммы и элементы архитектуры

Методы REST API для работы с диаграммами и элементами архитектуры. Общие правила (авторизация по
`X-Api-Key`, лимиты) — в [обзоре REST API](./README.md).

## Загрузка диаграмм

Метод создаёт новые BPMN-модели и обновляет существующие. Обычно его вызывают после выкладки приложения на Camunda, чтобы схемы в Stormbpmn совпадали с исполняемыми.

### Основной метод

**Путь:** `POST /public-api/v1/upload-diagrams`

### Структура запроса

Тело запроса — массив моделей, **не больше 20 в одном запросе**.

```json
[
    {
        "id": "Meeting_Scheduling:1:1123",
        "name": "Назначение встречи",
        "source": "CamundaMeetingsBackend",
        "xml": "<?xml version=\"1.0\" encoding=\"UTF-8\"?><bpmn:definitions ...>...</bpmn:definitions>"
    }
]
```

### Параметры запроса

| Поле       | Тип      | Обязательное | Описание                                                                      |
| ---------- | -------- | ------------ | ----------------------------------------------------------------------------- |
| **id**     | `string` | ✅           | Идентификатор модели в вашей системе; возвращается в ответе для сопоставления |
| **name**   | `string` | ✅           | Название модели, до 255 символов; **по нему модель ищется для обновления**    |
| **xml**    | `string` | ✅           | BPMN XML целиком, как строка JSON (кавычки и переносы экранируются)           |
| **source** | `string` | 📄           | Система-источник, попадает в комментарий версии                               |

### Создание или обновление

-   Если в команде **уже есть модель с таким же `name`**, загруженный XML становится её новой версией. Иначе создаётся новая BPMN-модель.
-   Если переименовать модель в Stormbpmn, связь пропадёт: следующая загрузка создаст новую модель со старым названием. Модели, обновляемые через API, не переименовывайте.
-   В одном запросе можно передать несколько версий модели с одинаковым `name`: они применятся по порядку, последняя станет текущей.
-   При каждой загрузке описание модели и комментарий версии заменяются служебной строкой вида `uploaded via Api from <source> at <время>, source id <id>`. Своё описание держите в другом месте, например в карточке процесса в реестре.

::: warning Какой XML подойдёт
Нужен полноценный BPMN 2.0 с графической частью схемы (`bpmndi:BPMNDiagram`), как его сохраняет Camunda Modeler. Файл только с логикой процесса, без координат фигур, не загрузится.
:::

### Структура ответа

```json
{
    "createdDiagrams": [
        { "stormDiagramId": "94d2e63f-f84a-40d4-b4a3-592b0cc7c7d9", "sourceDiagramId": "Meeting_Scheduling:1:1123" }
    ],
    "updatedDiagrams": [],
    "errors": {
        "emptyName": [],
        "nameTooLong": [],
        "emptyDefinition": [],
        "notXml": []
    }
}
```

`stormDiagramId` — идентификатор модели в Stormbpmn, `sourceDiagramId` — ваш `id`. В `errors` перечислены ваши `id` моделей, которые не загрузились; остальные модели пакета загружаются.

| Ключ в `errors`   | Причина                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `emptyName`       | пустое `name`                                                                                                                             |
| `nameTooLong`     | `name` длиннее 255 символов                                                                                                               |
| `emptyDefinition` | нет `xml`                                                                                                                                 |
| `notXml`          | в `xml` не XML                                                                                                                            |
| `BPMN_NOT_BPMN`   | XML не является BPMN-моделью                                                                                                              |
| `BPMN_MISSING_DI` | в BPMN нет графической части схемы                                                                                                        |
| `noEditAccess`    | модель с таким названием есть, но администратор, от имени которого работает ключ, не может её править (чужая личная модель, только чтение) |

Ключи `BPMN_NOT_BPMN`, `BPMN_MISSING_DI` и `noEditAccess` появляются в ответе, только если есть такие ошибки.

### Ошибки всего запроса

-   `400` `No diagrams in request` — пустой массив.
-   `400` `More than 20 diagrams in request` — больше 20 моделей.
-   `403` с `"code": "PLAN_LIMIT"` — новые модели не помещаются в лимит моделей тарифа; не загружается ни одна модель пакета.
-   `429` — превышена частота запросов, повторите после паузы из заголовка `Retry-After`.

### Пример: загрузить все .bpmn из папки

::: tip Автоматизация для Camunda
Скрипт на Python 3 без внешних библиотек: берёт все файлы `.bpmn` из папки, отправляет пакетами по 20, делает паузу между запросами и повторяет запрос при `429`. Подходит для шага в CI после выкладки.
:::

```python
import json, os, pathlib, sys, time, urllib.error, urllib.request

BASE = os.environ.get("STORM_URL", "https://stormbpmn.com")
KEY = os.environ["STORM_API_KEY"]
FOLDER = pathlib.Path(sys.argv[1] if len(sys.argv) > 1 else "src/main/resources/bpmn")

def send(batch):
    body = json.dumps(batch, ensure_ascii=False).encode("utf-8")
    for attempt in range(5):
        req = urllib.request.Request(
            f"{BASE}/public-api/v1/upload-diagrams", data=body, method="POST",
            headers={"X-Api-Key": KEY, "Content-Type": "application/json; charset=utf-8"})
        try:
            with urllib.request.urlopen(req) as resp:
                return json.load(resp)
        except urllib.error.HTTPError as e:
            if e.code == 429:
                time.sleep(int(e.headers.get("Retry-After", "1")) + 1)
                continue
            sys.exit(f"Ошибка {e.code}: {e.read().decode('utf-8', 'replace')}")
    sys.exit("Не удалось отправить пакет: слишком много повторов")

files = sorted(FOLDER.glob("*.bpmn"))
for i in range(0, len(files), 20):
    batch = [{"id": f.stem, "name": f.stem, "source": "ci",
              "xml": f.read_text(encoding="utf-8")} for f in files[i:i + 20]]
    result = send(batch)
    print(f"создано {len(result['createdDiagrams'])}, обновлено {len(result['updatedDiagrams'])}")
    for reason, ids in result["errors"].items():
        if ids:
            print(f"не загружены ({reason}): {', '.join(ids)}")
    time.sleep(1.1)  # на тарифе Команда — 1 запрос в секунду
```

Запуск: `STORM_API_KEY=ваш_ключ python upload_bpmn.py путь/к/папке`. Название модели здесь совпадает с именем файла без `.bpmn`; чтобы брать его из атрибута `name` процесса внутри файла, поменяйте строку с `"name"`.

## Управление элементами архитектуры

### Загрузка и обновление

**Путь:** `POST /public-api/v1/assets`

### Структура запроса

Тело запроса — массив элементов. Один запрос может и создавать, и обновлять элементы.

```json
[
    {
        "externalId": "CMDB-1042",
        "name": "1С:Бухгалтерия",
        "description": "<p>Учёт первичных документов и проводок</p>",
        "externalUrl": "https://cmdb.company.ru/systems/${externalId}",
        "type": "SYSTEM",
        "status": "PRODUCTION"
    }
]
```

### Параметры запроса

| Поле                      | Тип      | Обязательное | Описание                                    |
| ------------------------- | -------- | ------------ | ------------------------------------------- |
| **id**                    | `number` | 📎           | ID элемента в Stormbpmn, для обновления     |
| **externalId**            | `string` | 📎           | ID элемента во внешней системе              |
| **name**                  | `string` | ✅           | Название элемента                           |
| **type**                  | `enum`   | ✅           | `SYSTEM`, `DOCUMENT` или `CUSTOM`           |
| **customAssetDefinition** | `object` | для `CUSTOM` | Пользовательский тип: `{"id": "<UUID типа>"}` |
| **status**                | `enum`   | 📄           | Статус, по умолчанию `NEW`                  |
| **description**           | `string` | 📄           | HTML описание (unescaped)                   |
| **externalUrl**           | `string` | 📄           | Ссылка на элемент во внешней системе        |
| **color**                 | `string` | 📄           | Цвет в формате HEX, например `#4ECDC4`      |

### Типы элементов архитектуры

| Значение   | Описание                                                                  |
| ---------- | ------------------------------------------------------------------------- |
| `SYSTEM`   | Система                                                                   |
| `DOCUMENT` | Документ                                                                  |
| `CUSTOM`   | Элемент пользовательского типа: роль, данные, клиент и любые типы команды |

::: warning Изменение типов
Прежние встроенные типы (`CLIENT`, `ENTITY`, `DATA`, `UNSPECIFIED` и другие) стали пользовательскими. При передаче в `type` придёт ошибка: укажите `CUSTOM` и идентификатор типа в `customAssetDefinition`.
:::

```json
[
    {
        "externalId": "SEG-B2C",
        "name": "Частный клиент",
        "type": "CUSTOM",
        "customAssetDefinition": { "id": "3f0c2a8e-1b7d-4c55-9a61-0d2f7e4b9c10" }
    }
]
```

### Статусы элементов

| Значение          | Описание              |
| ----------------- | --------------------- |
| `NEW`             | Новый                 |
| `TRIAL`           | Тестирование          |
| `PRODUCTION`      | В эксплуатации        |
| `DECOMMISSIONING` | Вывод из эксплуатации |
| `ARCHIVE`         | Архив                 |

### Логика обновления

| Условие                  | Действие                                                                      |
| ------------------------ | ----------------------------------------------------------------------------- |
| **Только id**            | Обновление по внутреннему ID                                                  |
| **Только externalId**    | Обновление по внешнему ID; если элемента с таким `externalId` нет — создание |
| **И id, и externalId**   | Обновление по внутреннему ID                                                  |
| **Ни id, ни externalId** | Создание нового элемента                                                      |

### Ссылка на внешнюю систему

В `externalUrl` можно подставить шаблон `${externalId}`: Stormbpmn заменит его на внешний идентификатор элемента. Ссылки со схемами `javascript:`, `data:` и `vbscript:` не принимаются.

### Ответ

Массив сохранённых элементов в том же формате, с заполненными `id`, датами создания и изменения и логином того, кто изменил элемент последним. Если новые элементы не помещаются в лимит элементов архитектуры тарифа, придёт `403` с `"code": "PLAN_LIMIT"`.

## Получение списка диаграмм

### Основной метод

**Путь:** `GET /public-api/v1/get-diagram-list`

### Query-параметры

| Параметр | Тип      | Обязательный | Описание             |
| -------- | -------- | ------------ | -------------------- |
| **page** | `number` | 📄           | Номер страницы, с 0; по умолчанию 0 |

На странице 20 диаграмм, размер страницы не меняется. Чтобы получить все, увеличивайте `page`, пока не наберёте `totalElements` записей.

### Структура ответа

```json
{
    "totalElements": 223,
    "page": 0,
    "size": 20,
    "returnDiagrams": [
        {
            "id": "6b547a8f-a78f-4375-b39e-59c4afd9388e",
            "name": "Draft",
            "status": "NEW",
            "versionNumber": 3,
            "updatedBy": "kotov@bpmn2.ru",
            "teamFolderName": "Продажи",
            "createdOn": "2024-05-02T17:19:41.459888",
            "updatedOn": "2024-05-02T17:28:07.695362"
        }
    ]
}
```

::: info Права доступа
Список зависит от прав администратора команды, от имени которого работает ключ. В ответе есть и другие поля; читайте только нужные.
:::

## Получение диаграммы по ID

### Основной метод

**Путь:** `GET /public-api/v1/get-diagram-by-id`

### Query-параметры

| Параметр      | Тип    | Обязательный | Описание                           |
| ------------- | ------ | ------------ | ---------------------------------- |
| **diagramId** | `UUID` | ✅           | Уникальный идентификатор диаграммы |

### Ключевые поля ответа

| Поле              | Тип      | Описание                 |
| ----------------- | -------- | ------------------------ |
| **id**            | `UUID`   | Идентификатор диаграммы  |
| **name**          | `string` | Название диаграммы       |
| **body**          | `string` | XML содержимое диаграммы |
| **versionNumber** | `number` | Номер версии             |
| **status**        | `string` | Статус диаграммы         |
| **type**          | `string` | Тип диаграммы, например `BPMN` |

::: warning Изменения контракта
Список полей со временем дополняется: читайте только нужные (обычно `body`). Если диаграммы нет в команде ключа или нет доступа, придёт `404`.
:::

## Обновление описания элемента

### Основной метод

**Путь:** `POST /public-api/v1/element-description/{diagramId}/{elementId}`

### Параметры пути

| Параметр      | Тип      | Описание                |
| ------------- | -------- | ----------------------- |
| **diagramId** | `UUID`   | Идентификатор диаграммы |
| **elementId** | `string` | Идентификатор элемента  |

### Структура запроса

```json
{
    "description": "Подробное описание элемента",
    "duration": 3600,
    "externalLink": "https://wiki.company.com/process"
}
```

### Параметры запроса

| Поле             | Тип      | Описание                       |
| ---------------- | -------- | ------------------------------ |

| **duration**     | `number` | Длительность в секундах        |
| **externalLink** | `string` | Внешняя ссылка                 |

## Получение согласований

Метод отдаёт согласования, связанные с участником команды: где он согласующий или где он отправил модель на согласование.

### Основной метод

**Путь:** `GET /public-api/v1/approvals`

### Query-параметры

| Параметр        | Тип       | Обязательный | Описание                                                                          |
| --------------- | --------- | ------------ | --------------------------------------------------------------------------------- |
| **userEmail**   | `string`  | ✅           | Email участника команды                                                           |
| **status**      | `enum`    | 📄           | Фильтр по статусу                                                                 |
| **isApprover**  | `boolean` | 📄           | `true` — только где участник согласующий                                          |
| **isCreator**   | `boolean` | 📄           | `true` — только согласования, которые участник создал                             |
| **view**        | `enum`    | 📄           | `USER` (по умолчанию) — согласования участника; `TEAM` — все согласования команды |
| **diagramName** | `string`  | 📄           | Часть названия модели                                                             |
| **createdOn**   | `date`    | 📄           | Дата создания согласования, ISO 8601                                              |
| **approvedOn**  | `date`    | 📄           | Дата решения, ISO 8601                                                            |
| **page**        | `number`  | 📄           | Номер страницы, с 0                                                               |
| **size**        | `number`  | 📄           | Размер страницы, по умолчанию 20                                                  |

Сначала идут самые новые согласования. Если участника с таким email нет в команде ключа, придёт `403`.

### Статусы

Статусы в ответе:

| Значение   | Описание             |
| ---------- | -------------------- |
| `PENDING`  | Ожидает согласования |
| `ACCEPTED` | Принято              |
| `DECLINED` | Отклонено            |

В фильтре `status` дополнительно доступно `COMPLETED` — все завершённые: и принятые, и отклонённые. В ответе такого статуса нет.

### Структура ответа

```json
{
    "content": [
        {
            "id": "867bc39c-9145-4eb5-b59f-00545a6a9a3f",
            "approverEmail": "ivanova@company.ru",
            "approverName": "Иванова Анна",
            "createdBy": "petrov@company.ru",
            "diagramId": "fbeb4c64-e172-4e09-9fa1-6e509a11ffde",
            "diagramName": "Работа с подрядчиком",
            "diagramVersion": "11",
            "status": "PENDING",
            "comment": null,
            "createdOn": "2026-01-23T17:44:27.323817",
            "approvalTime": null
        }
    ],
    "totalElements": 1,
    "totalPages": 1,
    "size": 20,
    "number": 0
}
```

| Поле                                               | Описание                            |
| -------------------------------------------------- | ----------------------------------- |
| **approverEmail**, **approverName**                | Согласующий                         |
| **createdBy**                                      | Кто отправил модель на согласование |
| **diagramId**, **diagramName**, **diagramVersion** | Модель и согласуемая версия         |
| **comment**                                        | Комментарий согласующего            |
| **createdOn**                                      | Когда создано согласование          |
| **approvalTime**                                   | Когда принято решение               |
