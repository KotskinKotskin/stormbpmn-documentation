# Установка скриптом

Скрипт за 10–20 минут поднимает на одном сервере тестовую установку Stormbpmn: приложение,
PostgreSQL, S3-хранилище файлов, PlantUML, Gotenberg и Portainer. Дальше вы активируете
лицензию и проходите мастер первичной настройки.

## Что нужно заранее

| Что | Требование |
| --- | --- |
| Сервер | Ubuntu 22.04/24.04 или Debian 12, 64-bit; от 4 vCPU, 8 ГБ RAM, 50 ГБ диска |
| Права | `sudo` |
| Доступ в интернет | `registry.stormbpmn.com`, Docker Hub, `download.docker.com` (если Docker ещё не установлен) |
| Порты | `8081` — Stormbpmn, `8333` — S3 (браузер открывает по нему файлы), `9080` — Portainer |
| Доступ к образам | Логин и секрет robot-аккаунта из [портала Enterprise](/install/portal.md#доступ-к-образам) |

::: info Другие дистрибутивы
Скрипт сам ставит Docker только на Ubuntu и Debian. На Astra Linux, ALT Linux, РЕД ОС и других
системах сначала установите Docker Engine с плагином `docker compose`, затем запустите скрипт:
он увидит готовый Docker и пропустит установку. Нужны также `curl`, `openssl` и `jq`.
:::

## Установка

1. Зарегистрируйтесь в [портале Enterprise](/install/portal.md), если ещё не зарегистрированы,
   и в разделе **«Доступ к образам»** получите логин и секрет robot-аккаунта для
   `registry.stormbpmn.com`.

2. Скачайте файл настроек и заполните его:

   ```bash
   curl -O https://raw.githubusercontent.com/KotskinKotskin/stormbpmn-documentation/main/src/install/quickstart/script/install.env
   ```

   | Ключ | Описание | Пример |
   | --- | --- | --- |
   | `TIMEZONE` | Часовой пояс сервера и всех контейнеров | `Europe/Moscow` |
   | `STORMBPMN_VERSION` | Версия приложения, последняя — в [журнале изменений](/Changelog/README.md) | `9.13.172` |
   | `REGISTRY_USERNAME` | Логин robot-аккаунта из портала, **в одинарных кавычках**: в нём есть `$` | `'robot$stormbpmn-enterprise+company'` |
   | `REGISTRY_PASSWORD` | Секрет robot-аккаунта, в одинарных кавычках | `'<секрет из портала>'` |
   | `STORMBPMN_HOST` | Необязательно. IP или DNS-имя сервера, по которому пользователи откроют Stormbpmn. Если не задано, берётся первый IP сервера | `10.0.0.15` |

3. Скачайте скрипт рядом с `install.env` и запустите его:

   ```bash
   curl -O https://raw.githubusercontent.com/KotskinKotskin/stormbpmn-documentation/main/src/install/quickstart/script/install.sh
   chmod +x install.sh
   sudo ./install.sh
   ```

   Первый запуск приложения выполняет миграции базы, поэтому скрипт ждёт до 15 минут. В конце он
   выводит адрес Stormbpmn и **код активации** — строку из 64 символов.

В текущей папке появятся файлы:

| Файл | Что в нём |
| --- | --- |
| `docker-compose.yml` | Конфигурация всех контейнеров |
| `.env` | Лицензионный ключ `LICENSE_KEY_V2` (после установки пустой) |
| `credentials.txt` | Адреса и пароли: Portainer, PostgreSQL, ключи S3, `JWTSECRET` |
| `install.log` | Журнал установки |

::: important
Сохраните `credentials.txt` в защищённом месте. Пароли из него больше нигде не показываются.
:::

Что запущено:

| Контейнер | Порт на сервере | Назначение |
| --- | --- | --- |
| `stormbpmn` | `8081` | Приложение |
| `postgres` | `127.0.0.1:5432` (только с самого сервера) | PostgreSQL 17 с pgvector, база `stormbpmn` и расширения уже созданы |
| `seaweedfs` | `8333` | S3-хранилище [SeaweedFS](/install/production/components.md#s3-хранилище-для-фаилов), бакеты `storm-uploads`, `storm-users`, `storm-imports` |
| `plantuml`, `gotenberg` | — | Диаграммы PlantUML и выгрузка в PDF, доступны только приложению |
| `portainer` | `9080` | Веб-интерфейс для управления контейнерами |

## Активация лицензии

1. Скопируйте код активации из вывода скрипта. Его же показывает страница
   `http://<адрес сервера>:8081/admin-onboarding` в блоке **«Ваш активационный код»** — копируйте
   **весь код, без сокращения**.
2. В [портале Enterprise](/install/portal.md#лицензионныи-ключ) заведите инсталляцию (раздел
   **«Инсталляции»**), затем в разделе **«Лицензионные ключи»** выберите её, вставьте код и
   получите ключ.
3. Впишите ключ в файл `.env` рядом с `docker-compose.yml`:

   ```bash
   LICENSE_KEY_V2=<ключ из портала>
   ```

4. Перезапустите приложение и дождитесь, пока оно поднимется (1–2 минуты):

   ```bash
   sudo docker compose up -d stormbpmn
   ```

5. Обновите страницу `/admin-onboarding`: вместо предупреждения о ключе появятся данные лицензии
   и кнопка **«Начать настройку»**.

Для тестового контура, DR-площадки и каждого клона нужен отдельный ключ. Права AI и DES попадают
в ключ из договора лицензии. Подробнее — в разделе [«Как работают лицензии»](/operation/License.md#активация-инсталляции).

::: warning До активации не открывайте установку пользователям
Пока ключа нет, мастер не даст создать администратора, а войти в систему будет некому.
:::

## Мастер первичной настройки

Нажмите **«Начать настройку»** на `/admin-onboarding`. Мастер состоит из семи шагов:

1. **Администратор.** Укажите email и пароль первого администратора. Мастер создаст учётную
   запись и административную команду «Enterprise Admin» с полными правами и сразу выполнит вход.
   Запишите логин и пароль: второй раз первого администратора создать нельзя.
2. **Настройки.** Найдите настройку `baseUrl` и укажите адрес, по которому пользователи
   открывают Stormbpmn, например `http://10.0.0.15:8081`. Без него не работают ссылки в письмах
   и выгрузка в PDF.
3. **Брендинг.** Логотип и цвета. Шаг можно пропустить.
4. **Проверка системы.** Мастер проверяет базу, лицензию, адрес приложения, почту, S3,
   Gotenberg и PlantUML. Подробнее о каждой проверке — в разделе
   [«Проверка системы»](/operation/system-check.md).
5. **Резервные копии.** Укажите дату последней проверки восстановления из резервной копии.
6. **Поддержка.** Укажите ответственного администратора и подтвердите условия поддержки.
7. **Пользователи.** Шаблон приглашения для сотрудников. Нажмите **«Завершить настройку»**.

::: warning Почта на тестовой установке
Скрипт не настраивает отправку писем (`EMAIL_PROVIDER=nop`), поэтому проверка **«Почта (SMTP)»**
будет красной, а с красной проверкой мастер не завершается. Выберите одно из двух:

- подключите SMTP: добавьте в сервис `stormbpmn` в `docker-compose.yml` переменные
  `EMAIL_PROVIDER: smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM` (и `SMTP_USERNAME`,
  `SMTP_PASSWORD`, если сервер требует авторизацию), выполните
  `sudo docker compose up -d stormbpmn` и нажмите «Проверить снова»;
- или завершите настройку в обход: откройте `/admin-onboarding?skipChecks=1` и укажите причину,
  например «тестовая установка, почту подключим позже». Обход записывается — см.
  [«Обход проверок»](/operation/system-check.md#обход-проверок-skipchecks-1).
:::

После мастера создайте рабочую команду для сотрудников: администраторская команда только для
настройки системы. Как это сделать — в разделе
[«Создание рабочей команды для сотрудников»](./QUICKSTART_MANUAL.md#создание-рабочеи-команды-для-сотрудников).

## Если что-то пошло не так

- **Скрипт завершился с ошибкой.** Он откатывает свои изменения: останавливает контейнеры,
  удаляет их тома, `docker-compose.yml`, `.env` и `credentials.txt`. Исправьте причину из
  `install.log` и запустите скрипт снова. Если причина непонятна, пришлите `install.log` в
  поддержку.
- **Скрипт отказывается запускаться: «already installed».** В папке уже есть
  `docker-compose.yml` или на сервере есть том `postgres_data` от прошлой установки. Скрипт не
  трогает существующие данные. Для чистой установки удалите их вручную:
  `sudo docker compose down -v` в папке прошлой установки.
- **Docker Hub закрыт.** Образы PostgreSQL и Gotenberg есть в нашем реестре под тем же логином:
  `registry.stormbpmn.com/stormbpmn-enterprise/pgvector:pg17` и
  `registry.stormbpmn.com/stormbpmn-enterprise/gotenberg:8`. Замените их в
  `docker-compose.yml` (строки с подсказкой там уже есть).
- **Приложение не стартует.** Смотрите журнал: `sudo docker logs --tail 200 stormbpmn`.
- **Не открываются вложения и картинки.** Браузер пользователя должен открывать
  `http://<STORMBPMN_HOST>:8333`. Если сервер доступен пользователям под другим адресом, поправьте
  `S3_EXTERNAL_ENDPOINT` в `docker-compose.yml` и перезапустите `stormbpmn`.

::: tip Обновление версии
Поменяйте тег образа `stormbpmn` в `docker-compose.yml` на новую версию и выполните
`sudo docker compose up -d stormbpmn`. Перед обновлением сделайте резервную копию базы.
:::

## Важно: следующие шаги

:::danger Эта установка только для тестирования!
Описанная выше установка предназначена **только для проверки работоспособности** и знакомства с
системой. **Не используйте её для работы с реальными пользователями.**

Почему эта установка не подходит для продакшена:

-   **Нет SSL/HTTPS** — данные передаются в открытом виде
-   **Нет резервного копирования** базы и файлов
-   **Нет мониторинга** — проблемы и нагрузку не видно
-   **Упрощённая авторизация** — нет интеграции с корпоративными системами
-   **Нет почты** — пользователи не получат письма
:::

2. **[Безопасность](/configure/security/)** — HTTPS, авторизация и аудит
3. **[Администрирование системы](/operation/README.md)** — производительность, доступность, защита от потери данных

:::
