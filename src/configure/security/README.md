# Информационная безопасность

StormBPMN Enterprise обеспечивает высокий уровень информационной безопасности через многоуровневую систему защиты, включающую регулярное обновление зависимостей, сканирование уязвимостей и гибкие настройки доступа.

::: tip Принципы безопасности

-   **Минимальные привилегии** - только необходимые права
-   **Глубокая защита** - многоуровневая система безопасности
-   **Аудит всех действий** - полное логирование операций
-   **Шифрование данных** - защита паролей и конфиденциальной информации

:::

## Переменные окружения безопасности

Базовые настройки безопасности задаются через ENV переменные:

| Переменная                     | Описание                                | Пример значения                 | По умолчанию |
| ------------------------------ | --------------------------------------- | ------------------------------- | ------------ |
| **STORM_ALLOWED_ORIGINS**      | Разрешенные источники запросов (CORS)   | `https://stormbpmn.company.com` | `*`          |
| **STORM_DISABLE_SIMPLE_AUTH**  | Отключить встроенную авторизацию        | `true`                          | `false`      |
| **STORM_DISABLE_ENV_IN_UI**    | Скрыть ENV переменные в админке         | `true`                          | `false`      |
| **STORM_DISABLE_ANON_SHARING** | Запретить анонимный доступ к диаграммам | `true`                          | `false`      |
| **JWTSECRET**                  | Соль для шифрования паролей             | Минимум 64 случайных символов   | -            |
| **SESSION_EXPIRATION**         | Срок жизни сессии, **в секундах** (не больше 7776000) | `86400`              | 7 суток      |

::: warning Рекомендации по безопасности

-   **STORM_ALLOWED_ORIGINS:** Обязательно укажите конкретные домены вместо `*` в production
-   **JWTSECRET:** Используйте криптографически стойкую случайную строку длиной не менее 64 символов — токены подписываются алгоритмом HS512, которому нужен ключ ≥512 бит. С коротким ключом вход пользователей упадёт с `WeakKeyException`
-   **STORM_DISABLE_ENV_IN_UI:** Включите в production для скрытия конфиденциальных данных

:::

### Требования к паролям

При создании учётных записей, смене пароля и восстановлении доступа система проверяет пароль на соответствие следующим требованиям:

-   **Минимальная длина** — 8 символов
-   **Максимальная длина** — 72 байта в кодировке UTF-8
-   **Запрет распространённых паролей** — пароль не должен входить в список часто используемых значений

::: warning Ошибка при установке пароля
Если пароль не соответствует требованиям, система вернёт ошибку: «Этот пароль слишком распространён — выберите другой».
:::

В Enterprise-инсталляции требования можно ужесточить: длина и сложность, блокировка после неудачных попыток входа,
срок действия пароля, запрет повтора последних паролей — **[Политика паролей](./password-policy.md)**.

## Добавление собственных SSL-сертификатов

### Проблема

Если вы используете свой MinIO, S3 или другой HTTPS-сервис с самоподписанным сертификатом, Java внутри контейнера может не доверять ему. Это приведёт к ошибке:

```
javax.net.ssl.SSLHandshakeException: PKIX path building failed
```

### Решение

**Не создавайте новый пустой truststore только с корпоративным сертификатом.** При замене стандартного `cacerts` таким файлом Java перестанет доверять остальным корневым CA: это может нарушить HTTPS к S3, IdP и другим внешним сервисам. Сначала скопируйте **штатный** `cacerts` из той же версии образа StormBPMN, затем импортируйте корпоративный CA в копию.

### Шаг 1. Проверьте путь в запущенном контейнере

```bash
docker exec stormbpmn sh -c 'echo "$JAVA_HOME"; ls -l "$JAVA_HOME/lib/security/cacerts"'
```

Здесь и далее `stormbpmn` — имя контейнера в примере; замените его на своё. Путь `/opt/java/openjdk/lib/security/cacerts` ниже — **пример**, а не гарантия для всех сборок и версий Java. Используйте путь, проверенный в вашем образе.

### Шаг 2. Скопируйте стандартный truststore и добавьте CA

```bash
# -L позволяет скопировать сам файл, даже если cacerts является символической ссылкой.
docker cp -L stormbpmn:/opt/java/openjdk/lib/security/cacerts ./storm-cacerts
keytool -importcert \
  -file minio-ca.crt \
  -alias my-root-ca \
  -keystore ./storm-cacerts \
  -storepass changeit \
  -noprompt
```

Пароль `changeit` — обычный пароль стандартного Java `cacerts`; если в вашем образе он изменён, используйте фактический пароль. Не публикуйте файл truststore, если в нём есть закрытые ключи или другие чувствительные данные.

### Шаг 3. Подключите дополненный truststore

В `docker-compose.yml` (путь назначения должен соответствовать **вашему** контейнеру):

```yaml
services:
  stormbpmn:
    image: your-stormbpmn-image
    volumes:
      - ./storm-cacerts:/opt/java/openjdk/lib/security/cacerts:ro
```

После изменения пересоздайте контейнер. При обновлении образа/Java сверяйте расположение и содержимое `cacerts`, чтобы не использовать устаревшую копию системных сертификатов.

### Результат

Java продолжит доверять штатным публичным CA и дополнительно будет доверять импортированному корпоративному сертификату. Проверьте доступность и корпоративного S3, и остальных HTTPS-сервисов после перезапуска.

## Запуск контейнера с ограниченными правами

Образ (версии после 9.29.139) работает без root и без дополнительных привилегий:

-   процесс — uid 999 с группой 0; подходит и произвольный uid с группой 0 (OpenShift restricted-v2), но не другая группа;
-   capabilities не нужны: можно `cap_drop: [ALL]` и `no-new-privileges`;
-   корневая ФС может быть только для чтения. На запись нужны `/tmp` и `/var/cache/storm/djl`, **без `noexec`**: оттуда загружаются нативные библиотеки поиска по базе знаний;
-   в образе нет пакетного менеджера, curl и wget. Проверки здоровья — HTTP-пробы оркестратора или bash: `bash -c 'exec 3<>/dev/tcp/127.0.0.1/8082 && printf "GET /actuator/health/readiness HTTP/1.0\r\nHost: localhost\r\n\r\n" >&3 && cat <&3'`.

Пример для docker compose:

```yaml
services:
  stormbpmn:
    image: registry.stormbpmn.com/stormbpmn-enterprise/stormbpmn_fullstack_enterprise:<версия>
    read_only: true
    tmpfs:
      - /tmp:exec,size=1g
      - /var/cache/storm/djl:exec,size=1g
    cap_drop: [ALL]
    security_opt: [no-new-privileges:true]
    stop_grace_period: 90s
```

В Kubernetes то же задаётся в values чарта: `securityContext.readOnlyRootFilesystem: true` и `emptyDir` на `/tmp` и `/var/cache/storm/djl` через `extraVolumes` / `extraVolumeMounts`.

## Чек-лист безопасности

### Обязательные настройки

-   [ ] **CORS настроен** - указаны конкретные домены вместо `*`
-   [ ] **OAuth2 настроен** - корпоративная авторизация активна
-   [ ] **Регистрация отключена** - `showRegistraton = false`
-   [ ] **Анонимный доступ запрещен** - все параметры `*AnonAccess = false`
-   [ ] **ENV скрыты** - `STORM_DISABLE_ENV_IN_UI = true`
-   [ ] **Политика паролей** - [блокировка после неудачных попыток](./password-policy.md) включена, если используется встроенный вход

### Дополнительные меры

-   [ ] **Claims проверка** - настроена проверка групп/ролей в OAuth2
-   [ ] **Сетевая изоляция** - доступ только из корпоративной сети
-   [ ] **SSL/TLS** - обязательное шифрование трафика
-   [ ] **Резервное копирование** - регулярные бэкапы базы данных
-   [ ] **Мониторинг** - отслеживание подозрительной активности
-   [ ] **Аудит-логирование** - [журнал действий](./audit-logging.md) включён
-   [ ] **Ограниченные права контейнера** - корневая ФС только для чтения, `cap_drop: ALL` ([запуск контейнера с ограниченными правами](#запуск-контейнера-с-ограниченными-правами))
-   [ ] **Подпись образа проверена** - команда `cosign verify` есть в описании каждой версии
