# Self-hosted LLM — выбор модели

AI-чат Stormbpmn работает через инструменты: создаёт и правит диаграммы, заводит роли и документы, привязывает их к процессу, отвечает на вопросы по продукту через базу знаний. По умолчанию движком служит внешняя модель с OpenAI-совместимым API. Её можно заменить на **собственную модель на своём GPU**: данные не покидают контур, а стоимость не зависит от числа запросов.

На этой странице — какую модель мы рекомендуем, на каком железе, с какой скоростью и сколько токенов тратит один пользователь. Все цифры сняты на нашем облаке Stormbpmn, где эта же конфигурация обслуживает AI-чат для всех пользователей.

::: tip Раздел из двух частей
**Эта страница** — что выбрать и сколько это тянет. Как поднять модель — в статье **[Развёртывание на vLLM](./deploy-vllm.md)**: готовый docker-compose, разбор флагов, диагностика.
:::

::: tip Смена модели — две настройки, без правки кода
Движок переключается параметрами `bpmnAiCompletionBaseUrl` и `bpmnAiCompletionModel` в настройках приложения. Формат OpenAI-совместимый, поэтому подходят и облачные API, и собственный сервер на vLLM.
:::

## Рекомендация

| | Что ставить |
|---|---|
| **Модель** | **Qwen3.8-27B** |
| **Сборка весов** | `unsloth/Qwen3.8-27B-NVFP4` (квантование NVFP4, около 22 ГБ видеопамяти) |
| **GPU** | 1× NVIDIA RTX PRO 6000 Blackwell, 96 ГБ |
| **Движок** | vLLM `v0.27.1` с исправлением для MTP и кэша префиксов (см. [Развёртывание на vLLM](./deploy-vllm.md)) |
| **Контекст** | 262 144 токена (полное окно модели) |
| **Параллельность** | до 16 запросов одновременно |
| **Ускорение генерации** | спекулятивное декодирование MTP, 3 токена вперёд |
| **Размышления** | в Stormbpmn — `enabled` (`bpmnAiChatThinking`), на сервере по умолчанию выключены |
| **Качество** | 93% на нашем наборе проверок AI-чата (выбор инструмента, построение процесса, ответы по базе знаний) |

Почему эта модель: она уверенно ведёт длинные цепочки вызовов инструментов, ищет ответы в базе знаний, а не выдумывает, и собирает крупный процесс за один заход. При этом веса занимают меньше четверти карты, и остаток видеопамяти уходит на KV-кэш: полное окно контекста и 16 параллельных запросов.

### Если GPU не Blackwell

Квантование NVFP4 работает только на картах NVIDIA Blackwell (RTX PRO 6000, RTX 50xx, B200). На Hopper (H100, H200) и Ada (L40S, RTX 6000 Ada) берите сборку в FP8: `Qwen/Qwen3.8-27B-FP8`, около 28 ГБ под веса. Остальные флаги те же. Скорость на этих картах мы не замеряли, ориентируйтесь на собственный прогон.

На карте с 48 ГБ видеопамяти уменьшите `--max-model-len` до 131 072 и `--max-num-seqs` до 8: чату Stormbpmn этого окна хватает. Такую конфигурацию мы не проверяли; одновременных запросов на ней поместится меньше, чем в замерах ниже.

## Скорость на одной карте

Замер на RTX PRO 6000 Blackwell с конфигурацией из [Развёртывания на vLLM](./deploy-vllm.md), ответы по 512 токенов:

| Одновременных запросов | Генерация, суммарно ток/с | На один запрос, ток/с |
|:---:|:---:|:---:|
| 1 | 110 | 110 |
| 4 | 298 | ~75 |
| 8 | 742 | ~93 |
| 16 | 1 252 | ~78 |

Ответ на 512 токенов приходит за 4–6 секунд. Суммарная скорость растёт почти линейно до 16 запросов: одна карта держит пиковую нагрузку без очереди.

## Сколько токенов тратит один пользователь

Данные AI-чата облака Stormbpmn за 12.10–01.11.2026: 1 963 пользователя, около 9 900 ходов чата, все пользователи без фильтров по тарифу. «Ход» — одно сообщение пользователя и весь ответ на него, включая вызовы инструментов.

| | Вход, медиана | Вход, 90-й перцентиль | Выход, медиана | Выход, 90-й перцентиль |
|---|---:|---:|---:|---:|
| **Один ход** | 150 тыс. | 560 тыс. | 4,7 тыс. | 25 тыс. |
| **Пользователь за день работы с чатом** | 370 тыс. | 2,5 млн | 15 тыс. | 79 тыс. |
| **Пользователь за 3 недели** | 400 тыс. | 3,9 млн | 16 тыс. | 107 тыс. |

Как читать эти цифры:

- **Вход в десятки раз больше выхода**, потому что ход состоит в среднем из 7 запросов к модели: модель вызывает инструмент, получает результат и продолжает. Каждый запрос заново несёт системный промпт, описания инструментов и историю диалога. Фактический размер контекста одного запроса — около 43 тыс. токенов (медиана). Повторяющаяся часть берётся из кэша префиксов vLLM и почти не нагружает карту. У облачных провайдеров с кэшированием промпта она тарифицируется по сниженной цене.
- **Выход** включает размышления модели: в облаке они включены, и около 90% ходов идут с ними.
- **Пользователь работает с чатом не каждый день**: в среднем 1,4 дня за 3 недели. Средние значения выше медианы в 3–4 раза: немного активных пользователей строят большие процессы и тратят основную часть токенов.

Для планирования бюджета у внешнего провайдера считайте от **дня работы с чатом**: в среднем 1,35 млн токенов на вход и 34 тыс. на выход на одного пользователя.

## Сколько пользователей тянет одна карта

Одна RTX PRO 6000 с этой конфигурацией обслуживает весь AI-чат облака Stormbpmn. Нагрузка по данным чата за 12.10–01.11.2026 и логам vLLM за неделю до 04.11.2026:

| Показатель | Значение |
|---|---|
| Пользователей чата в будний день | 150 (медиана), до 190 |
| Пользователей чата за неделю | 700–850 |
| Пиковый час | 32 пользователя, 73 хода |
| Одновременных запросов в пике | 16, ровно `--max-num-seqs` |
| Средняя генерация в будни | 230–330 ток/с, при доступных 1 250 |
| Заполнение KV-кэша в пике | до 82% |

Ориентир: **одна карта — до 200 активных пользователей чата в день**. Ограничивает не скорость генерации, а число одновременных запросов и KV-кэш. Если в логах vLLM стабильно растёт `Waiting` или KV-кэш подходит к 100%, ставьте вторую карту с тем же compose и балансировщиком перед ними.

## Что не рекомендуем

| Вариант | Почему нет |
|---|---|
| MTP на 4 токена вперёд | на vLLM `v0.27.1` падает с `CUDA illegal memory access` при 16 одновременных запросах |
| SGLang со спекулятивным декодированием DFlash на одной карте | быстрее на 1–4 запросах (до +40%), но на 16 запросах на 36% медленнее vLLM |
| DeepSeek V4 Flash | не помещается в одну карту 96 ГБ, а на наших проверках работает на уровне Qwen3.8-27B |
| vLLM `latest` вместо закреплённой версии | новая версия может поменять поведение парсеров инструментов и кэша. Обновляйте осознанно, после прогона на тестовом стенде |

## Что учесть до запуска

- **Парсер вызовов инструментов** обязателен: `--enable-auto-tool-choice --tool-call-parser qwen3_coder`. Без него модель пишет «готово», ничего не сделав.
- **Размышления**: в Stormbpmn поставьте `bpmnAiChatThinking = enabled` и включите стриминг ответа, тогда пользователь видит ход мыслей модели. Без стриминга поставьте `disabled`. Подробнее — [Размышления (thinking)](../AI_CHAT.md#размышления-thinking).
- **Шлюз перед моделью** (корпоративный прокси, API-gateway) должен пропускать потоковые ответы. Если он отвечает `400` на `"stream": true`, выключите тумблер «Стриминг ответа» — см. [Настройка AI-ассистента](../AI_CHAT.md#стриминг-ответа).
- **Системный промпт** менять не нужно.

## Как переключить модель

Параметры задаются в настройках приложения (раздел AI) и применяются **без перезапуска**:

| Параметр | Что задаёт | Значение |
|---|---|---|
| `bpmnAiCompletionBaseUrl` | Адрес OpenAI-совместимого сервера, **без** `/v1` (Stormbpmn допишет сам) | `http://<llm-host>` |
| `bpmnAiCompletionModel` | Имя модели на сервере, ровно `--served-model-name` | `qwen3.8-27b` |
| `bpmnAiCompletionTemperature` | Температура | `0.2` |
| `bpmnAiChatThinking` | Размышления | `enabled` (со стримингом) |

::: tip Как переходить с другой модели
Если у вас уже работает другая модель, поднимите новую рядом и переключите на неё часть пользователей или тестовый стенд. Через 1–2 недели сравните оценки ответов в чате и время ответа, затем переключайте всех.
:::
